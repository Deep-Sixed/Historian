# RAG Versions Overview
### User

what versions of RAG were we using

### Assistant

From the prior discussions around Nexus, Agent Pi, and Hermes, the stack evolved through several forms of RAG:

| Stage | RAG Type | Status | Purpose |
|---------|----------|---------|---------|
| **Chunk RAG** | Traditional vector/chunk retrieval | Early | Inject relevant documents into the 8K context window |
| **LightRAG** | GraphRAG-style knowledge graph retrieval | Prototype / failed pipeline | Structured document ingestion |
| **Hindsight Memory** | Experience GraphRAG | Current working system | Retrieval over past tasks and agent experiences |
| **Datacore** | Long-term memory layer | Partially wired | Cross-session persistence and artifact history |
| **Summarizer + Rolling Memory** | Compression RAG | Active | Preserve information beyond context limits |

### In chronological order

1. **Traditional Chunk RAG**
   - Embeddings + chunks.
   - Used because Gemma 4 12B was limited to ~8K context.
   - Combined with summaries and tool calls.

2. **LightRAG**
   - A GraphRAG implementation.
   - Intended to build a knowledge graph over documents.
   - Eventually considered unsuccessful and retired.

3. **Hindsight Memory**
   - GraphRAG over experiences rather than just documents.
   - Stores:
     - task history,
     - artifacts,
     - decisions,
     - previous outcomes.
   - Became the primary memory substrate.

4. **Datacore (Hermes)**
   - Long-term persistent memory.
   - Intended to provide:
     - retrieval,
     - task memory,
     - cross-session continuity.
   - Earlier discussions noted that parts of it were not fully connected into the runtime loop.

So the sequence was essentially:

```text
Classic Chunk RAG
        ↓
LightRAG (GraphRAG prototype)
        ↓
Hindsight Memory (working GraphRAG)
        ↓
Datacore persistent memory
```

Conceptually, the stack had shifted from:

```text
RAG over documents
```

to

```text
RAG over knowledge graphs
```

and finally toward

```text
RAG over agent experiences + persistent memory
```

which is closer to an episodic memory architecture than a conventional vector-database RAG system.
