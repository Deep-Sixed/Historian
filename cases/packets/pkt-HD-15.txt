## What this is

**Hermes Agent Desktop** is Nous Research’s open-source agent runtime. The desktop page lists **macOS, Windows, and Linux** install paths, marks it **MIT licensed**, and shows the current desktop page version as **Hermes Agent v0.15.2**. citeturn181584view0

The bigger project is not just a chat UI. It is an autonomous agent framework with:

| Area | What Hermes does | Nexus relevance |
|---|---|---|
| **Memory** | Stores persistent memory in `~/.hermes/memories/` using `MEMORY.md` and `USER.md`. citeturn752363view0 | Similar role to Agent 9 / Datacore, but much smaller and file-based by default. |
| **Skills** | Uses `~/.hermes/skills/` as the source of truth; skills are `SKILL.md`-style procedural documents. citeturn752363view1 | Directly relevant to your “are agents Python or SKILL based?” question. Hermes is **both**: Python runtime plus skill documents. |
| **MCP** | Can connect to external MCP servers, including filesystems, databases, GitHub, browser stacks, and internal APIs. citeturn752363view2 | Relevant to Nexus Agent 7 / MCP Control Panel and Agent 9 Datacore exposure. |
| **Subagents** | Supports isolated subagents with their own conversations, terminals, and Python RPC scripts. citeturn181584view0 | Relevant to Agent 10 recruiter-correspondence worker design. |

## My read for Nexus / Agent 10

**Do not install it directly with the one-liner on JARVIS.**

The docs’ quick install uses:

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

and the Windows installer explicitly handles its own `uv`, **Python 3.11**, Node.js, ripgrep, ffmpeg, and Git Bash stack. citeturn222371view0turn617668view0 That conflicts with your Nexus rule: Agent 10 should stay **inside Nexus**, and Nexus runtime lanes should not drift into unmanaged external paths.

## Best use

Treat Hermes as a **reference/template**, not the live Agent 10 runtime.

For your Agent 10 design, the useful pieces are:

1. **Skills model**  
   Use Hermes-style `SKILL.md` files for recruiter correspondence workflows.

2. **Memory separation**  
   Map Hermes memory concepts into **Agent 9 Datacore / Hindsight**, not `~/.hermes/memories`.

3. **MCP integration**  
   Expose Nexus-owned MCP tools only through Agent 7 / Nexus MCP Control.

4. **Subagent pattern**  
   Agent 10 can spawn bounded task workers for:
   - recruiter reply drafting
   - job-description summarization
   - email classification
   - CRM update suggestions

5. **Provider routing**  
   Replace any Hermes model/provider defaults with your approved lane:
   - **llama.cpp**
   - **agent10/Open WebUI frontend/router**
   - **no Ollama**

## Safe Nexus ingest pattern

Use a vendored/reference checkout, not a host install:

```bash
cd /home/jarvis/projects/nexus
mkdir -p vendor/reference
git clone --depth 1 https://github.com/NousResearch/hermes-agent vendor/reference/hermes-agent
```

Then inspect only:

```bash
cd /home/jarvis/projects/nexus/vendor/reference/hermes-agent
find . -maxdepth 2 -type f | sort | head -100
```

## Recommendation

For Nexus, Hermes should become:

**`vendor/reference/hermes-agent` → design reference for Agent 10 skills, memory loop, MCP wiring, and subagent architecture.**

Not:

**`~/.hermes`**, host-installed CLI, unmanaged Python, or an external Agent 10 runtime.
