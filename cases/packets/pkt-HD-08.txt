# Installing pi-llama.cpp safely
### User

I am install pi-llama.cpp on thanatos but I already have LM studio & Ollama

### Assistant

I’ll treat Thanatos as a separate host and avoid disrupting LM Studio/Ollama. The safe path is to install `pi-llama.cpp` in its own directory, bind it to its own port, and only disable LM Studio/Ollama later if you choose.

### Assistant

Yes. Keep all three, but **do not let them share ports**.

## Safe layout

- **LM Studio**: leave alone
- **Ollama**: leave alone unless it is eating RAM/CPU
- **pi-llama.cpp**: install isolated, use its own runtime/model path

`pi-llamacpp` is a Pi extension that downloads/builds a matching `llama.cpp` runtime and starts/stops `llama-server` automatically with Pi. citeturn926538search0

## Check conflicts first

```bash
ss -ltnp | egrep ':(11434|1234|1235|8080|9000|9001)\b' || true
systemctl --user status ollama 2>/dev/null || systemctl status ollama 2>/dev/null || true
pgrep -af 'lmstudio|ollama|llama-server|pi' || true
```

## Install isolated

```bash
mkdir -p ~/projects/pi-llama ~/models/pi-llama
cd ~/projects/pi-llama

# install Pi extension
pi install github:mitsuhiko/pi-llamacpp
```

## If Ollama is hogging Thanatos

```bash
systemctl --user stop ollama 2>/dev/null || sudo systemctl stop ollama
```

Do **not** uninstall Ollama or LM Studio yet. First get Pi working, then decide what stays.

## Autostart it on login

```bash
mkdir -p ~/.config/autostart
cat > ~/.config/autostart/pi-llama-tray.desktop <<'EOF'
[Desktop Entry]
Type=Application
Name=Pi llama.cpp Tray
Exec=/home/$USER/.local/bin/pi-llama-tray
X-GNOME-Autostart-enabled=true
EOF
```

Fix the `$USER` issue:

```bash
sed -i "s|\$USER|$USER|g" ~/.config/autostart/pi-llama-tray.desktop
```

## Notes

- This gives you a **green-ish play icon when running** and a **stop icon when not running**.
- It does **not start/stop Pi** yet; it only shows status.
- It checks for `pi`, `llama-server`, or `pi-llama` processes.
